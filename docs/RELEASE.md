# Release acceptance — незакрытая работа

Эта ветка заменяет архитектуру раннера и добавляет перечисленные в README системы. Она **не закрывает весь пользовательский запрос на полноценную release-quality игру**. Доступен код и CI; Roblox Studio, live playtest и авторизованная загрузка новых mesh/audio assets в текущей среде отсутствуют.

## Что необходимо довести до релиза

1. **Физика и сеть.** В Studio пройти все 36 этапов на BMX первого уровня, повторить на телефоне; проверить прыжки после приземления, узкие мосты, виражы, посадку, R6/R15, reset и восстановление камеры. Сравнить отзывчивость при 80–200 мс RTT: текущий контроллер server-owned, client prediction пока отсутствует. Нужен замер, а не обещание хорошей отзывчивости.
2. **Environment art.** Текущие секции собираются из нативных деталей. Заменить повторяющиеся фасады и растения авторскими MeshParts, добавить material/texture-наборы, вручную поставить уникальные landmarks и декор. Привести Afterhours к полноценному ночному настроению: сейчас общий дневной Lighting для всех миров. Сохранить читаемость поверхности и препятствий.
3. **Ассеты.** Подготовить/загрузить разрешённые для universe mesh/audio assets; проверить ownership/moderation. Сейчас внешние Toolbox-скрипты и непроверенные чужие ID не загружаются. Нет завершённого набора музыки, SFX, иконок магазина/страницы игры и анимации педалирования. Колёса и руки R15 анимированы; R6 использует стандартную посадку.
4. **Контент.** Есть 36 этапов из шести типов, но нет ручной проверки темпа/сложности и полного релизного объёма разнообразия. Протестировать медальные пороги, доход, стоимость всех покупок и улучшений. Нужна пользовательская проверка retention, а не только работающая экономика.
5. **Мультиплеер.** Start Server с 11 клиентами: уникальные гаражи, гости, два одновременных заезда, одинаковые характеристики гонки, выход из очереди, выход во время отсчёта, финиш, timeout и повторная гонка. Max Players = 11 выставляется в настройках experience; исходный publish endpoint его не меняет. При большем количестве игроков лишние пользователи пока появляются в общем хабе без личного гаража.
6. **Профили.** На тестовом опубликованном place проверить миграцию v1/v2, выход/вход после покупки, ежедневную награду, сохранение дробного рекорда, аварийное закрытие. Unit-тесты используют fake DataStore и не проверяют квоты/задержки Roblox. При недоступном DataStore игрок не допускается, чтобы не затирать сохранение. Studio должен иметь API Services или использовать отдельный тестовый universe.
7. **Производительность.** Профилировать MicroProfiler на телефоне, а не только desktop: 11 велосипедов, витрины, прозрачное стекло, StreamingEnabled, телепортация между мирами, UI в портретной/альбомной ориентации. Проверить stream-in финишных платформ. Пока нет измеренных FPS, памяти и traffic budget.

## Защищённые инварианты

- Награды и гонки рассчитывает сервер; клиент отправляет только действия и управляющий ввод.
- Чекпоинты принимаются последовательно с серверной позиции физического велосипеда.
- У серверного ввода есть ограничение частоты, проверка типов/NaN/диапазонов и таймаут отпускания газа.
- Продолжение с сохранённого этапа не ставит рекорд полного прохождения.
- Покупки и daily не списывают/выдают повторно при простом повторе запроса.
- Session lock не разрешает другому серверу перезаписать профиль; ошибка чтения не создаёт новый профиль поверх старого.
- PR собирает артефакт без публикации. Merge в main публикует в существующий place.

## Что проверено автоматически

- Все Luau-скрипты компилируются.
- 109 assertions: экономика, 36 секций, пределы уклонов/разрывов, покупки, ежедневные награды, миграция, fractional PB, блокировка сессии, ошибки чтения и stale saves.
- Rojo собирает `CITY-RUSH.rbxlx`.
- Контракт исходной публикации и отсутствие старой lane-runner логики проверены `tools/validate.py`.

Численные проверки геометрии проверяют параметры, а не фактическую проходимость в движке. Release approval возможен после перечисленных engine/art проверок; успешный CI сам по себе не означает готовность к релизу.
